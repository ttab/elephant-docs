# Elephant Docs

Developer documentation generator for elephant.

Work in progress, test using:

``` shellsession
go run ./cmd/elephant-docs -out static -serve :8080
```

## Configuration

[`elephant-docs.json`](elephant-docs.json) declares the modules to clone, the
APIs each one exposes and the document schema repository. It is read with
`DisallowUnknownFields`, so a misspelled setting fails the build rather than
being silently ignored, and the protocol gate versions are parsed and
validated at load.

### Modules and APIs

```json
{
  "title": "Core APIs",
  "name": "github.com/ttab/elephant-api",
  "protoRoot": "",
  "vendorRoot": "rpc/vendor",
  "apis": {
    "repository": {
      "title": "Repository",
      "protocols": {
        "connect": {"from": "v0.25.0"},
        "twirp": {"until": "v1.0.0", "note": "..."}
      }
    }
  }
}
```

`protoRoot` is the directory the module's API directories live in, relative to
the repository root. It defaults to the repository root, which is the original
layout; a repository generated by the `rpc` mage namespace keeps them under
`rpc` instead. Older versions that predate a move are still found in the
repository root, so a module can change layout without losing its history. An
API that no version of its module declares fails generation rather than
silently disappearing from the menu, the home page and the version pages.

`vendorRoot` is where the module vendors protobuf files it imports from other
modules, `rpc/vendor` by default. Its contents are excluded from the API file
walk and used to resolve imports that no configured module provides. A
vendored file is never documented as part of an API: it belongs to the module
it was copied out of.

`protocols` declares from and until which module version the deployed service
serves a protocol, and its versions are validated at load. An API with no
`protocols` entry is documented as Twirp only.
